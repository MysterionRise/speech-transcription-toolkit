The transformers backend no longer fails with "Could not load this library: …torchcodec…" when torchcodec is installed but can't load. The `diarize` extra installs torchcodec, and on Linux its PyPI build needs PyPI's CUDA build of torch, so this happened with a CPU-only torch or one from another CUDA index. transformers' pipeline imported torchcodec on every call, though the backend passes it audio that ffmpeg has already decoded; the backend now tells the pipeline torchcodec isn't there.
