`transcribe-server` keeps answering under load: one worker runs the model behind a bounded queue (`--max-queue`, default 8), and a request that finds the queue full gets a 503 at once, with `Retry-After`, before its upload is read. `/health` and `/v1/models` answer straight away however busy the model is, and `/health` reports the queue; a request whose client disconnects while it waits is dropped. New options: `--max-audio-seconds` refuses longer audio with a 400 without decoding the rest, `--cors-origin` lets web pages call the API from the browser, and `--docs`/`--no-docs` turns the API docs on or off. The server's own log (undecodable uploads, dropped requests, and errors with their tracebacks) goes to stderr.
